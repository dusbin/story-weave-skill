给接手这个技能的人。**动手改之前建议先读完**——这里记的都是"踩过一次、不想再踩"的东西。

## 一、设计上的根本取舍

### 1. 引擎取证，模型判定

反例认识：让 LLM 直接判断"这段话符不符合常识"，得到的往往是"看起来挺合理"或"某处可能有问题"，
既不可复现、也无法核对，而且它会把"设定允许的"和"常识错误的"混为一谈。

所以本技能把工作切开：

| | 谁做 | 例子 |
|---|---|---|
| 可计算的量级判定 | **引擎**（79 条确定性规则） | "跑了三百公里、两小时"→ 平均 150 km/h，超出人体上限 |
| 需要理解语义的判定 | **模型**（23 条清单项） | "他为什么突然原谅了她"→ 有没有铺垫 |

引擎的职责是**取证与收窄**：把"要判断什么"和"原文在哪一句"准备好，让模型/人只做它擅长的判断。
引擎**不**评价文笔，模型**不**臆造常识错误。

### 2. 误报的代价远高于漏报

报告是以"常识错误"的名义写给作者看的。一次误报（比如把"三十岁"和"十五岁离开家"判成矛盾）
会让作者开始怀疑所有判定。所以全库遵守同一纪律：

> **判不了就不报。** 解析失败返回 `null` 并跳过，绝不猜。

这条纪律贯穿实现：`parseNumber('十几')` 返回 `null`；推不出明确的禁止短语就退回清单项；
同一事件重述才判"改写事实"，仅仅"出现了不同年龄"不判。

### 3. 结论只看硬伤数

分数只是概览（`100 − Σ(硬伤×10 + 可疑×4 + 留意×1)`）。若把"得分 90"当成"没问题"，
就会漏掉那唯一一处硬伤。故 `verdict` 以 blocker 数为准，且在报告里显式写出这条规则。

### 4. 人工确认是硬闸门，不是建议

方案未经 `sw confirm` 一律拒绝进入写作。确认结果写回 `plan.json`：
每条修改点带 `decidedAt` / `userNote`，方案改动记 `status.history`（含**改动前后**的值）。
理由：方向错了再往下写，写得越流畅返工越贵。

## 二、踩过的坑（都有回归测试盯着）

### 解析类：静默算错比报错更危险

| # | 症状 | 根因 | 现在 |
|---|---|---|---|
| 1 | 「三十公里」被算成 10 公里 | `kit.mjs` 里的中文数字片段只匹配**单个**字，正则从「十」开始匹配上了 | 数量词片段用 `{1,8}` |
| 2 | 「半小时」= 1.5 小时 | 主分支把裸「小时」当系数 1，再加「半」的 0.5 | 分支优先级 + 非重叠推进 |
| 3 | 「一个半小时」= 0.5 小时 | 为修 #2 加的"前面是半就跳过"把真正的小时也跳掉了 | 同上 |
| 4 | 「三天三夜」= 6 天 | 「三天」「三夜」各计 24 小时 | 「夜」紧跟 天/日 时跳过；单独「夜」= 12h |
| 5 | 「冬天/今天/小时候/那天」被当成 1 天 / 1 小时 | 数量词可选，裸单位字被当成"1 个单位" | 必须显式带数量词 |
| 6 | 「九千九百九十九」= 10890 | 「一千二」的省略单位习惯按**最大单位**缩放，而应按**紧邻单位** | 用 `lastUnit` 而非 `highestUnit` |
| 7 | 「一两」= 2（约数被当确定值） | 连续数字字取最后一个 | 连续数字字无「零」→ `null` |
| 8 | 「零下二十度」解析为 `null` | 正则只吃阿拉伯数字 | 支持中文数字 |
| 9 | 「一九九八年」算成 3109 | 用 `indexOf` 取位值，而 `'〇'` 占一个下标导致整体错位 | 显式映射表 |
| 10 | 未指定年份被当成公元 0 年，凭空判出"秦汉" | `Number(null) === 0` 且 `isFinite(0)` 为真 | 显式判 `null/undefined/''` |

### 抽取类

| # | 症状 | 根因 | 现在 |
|---|---|---|---|
| 11 | 抽出不存在的人物「任摇了」 | 对话归属动词表里放了双字词「摇头」，`主任摇了摇头` 被切成「任摇了」+ lookahead「摇头」 | 归属动词只放**单字** |
| 12 | 「小时候」被当成昵称「小时」 | 昵称规则没黑名单 | `NICKNAME_STOPWORDS` |
| 13 | 亲属称谓「哥哥」被判成主角，真正有台词的「林晚」成配角 | 按**累计**得分排序，高频称谓占优 | 按**最强单条证据**排序 |
| 14 | 主角本人被推荐为"番外主角" | 判主角用"台词≥2"，只说过一句的真正主角被判成配角 | 主角 = 得分最高者，番外候选排除主角 |
| 15 | 「都市重生」被判成现实标尺 | 关键词表缺「重生/穿越」，于是"先知"会被当成违反常识 | 新增 `timetravel` 体裁 + 冲突检测 |

### 结构与流程类

| # | 症状 | 根因 | 现在 |
|---|---|---|---|
| 16 | `sw confirm` 未传 `--scale` 即崩溃 | `setIf(cond, desc, fn)` 的 `desc` 是模板字符串，函数实参**提前求值** | `desc` 改为惰性函数 |
| 17 | 留痕记成「短篇 → 短篇」 | 先执行改动再生成描述，读到的是改后的值 | 描述在 `fn()` **之前**求值 |
| 18 | 引号被撕成两半，出现只含 `」` 的碎片 segment | 断句用 `/(?<=[。！？])/`，看不见引号 | 括号栈感知的 `splitSentences` |
| 19 | 最后一节指令里「收束要求」从不出现 | 渲染函数读的是 `plan.beats` 原始元素上的 `isLast`（不存在） | 在渲染函数内部按 `i` 与总数判定 |
| 20 | `# 文档标题` 被当成"第 1 节" | 未区分标题层级 | 混用层级时以**最深**层级分节 |
| 21 | 内部一致性 finding 缺 `ruleId`/`category`，报告显示 `undefined` | 内部检查直接 `push`，未走 `normalizeFinding` | 补齐元数据 |
| 22 | 模型判 fail 时，结论挂在一条无关原文上 | 直接取清单项的第一条**候选**证据 | 模型可指定 `quote`/`line`，优先采用 |
| 23 | 引擎一份切分实现、`text.mjs` 另一份，行号可能对不上 | `engine.mjs` 里有内联的重复实现 | 统一走 `text.mjs` 的 `scanSegments` |
| 24 | 「没能结成金丹」被判成违反设定（硬伤） | 否定检测只判断"前 4 字是否以否定字**结尾**"，「没能」结尾是「能」 | 枚举以情态词收尾的复合否定 |

> **⚠️ 给规则作者的坑（subagent 上报，很重要）**
> `splitSentences` 按句末标点切分。**凡是用配对引号做判据的规则**
> （如 `/「[^」]+」/` 判断某句是否台词）都会失效——因为引号可能跨段。
> 现在虽然实现了引号感知，但**跨段引号（引号内包含多个句子）仍会各自成段**，
> 规则里请用"只认开头引号"或"引号 + 关键词同段出现"的写法。

## 三、已知误报风险（阈值偏严的地方）

以下都是刻意选的保守阈值。**若要调，请连同该模块的测试一起调。**

| 规则 | 阈值 | 可能误报的场景 |
|---|---|---|
| `PHY-002` 长时奔跑 | 0.5–3.5h 用 21 km/h；>12h 用 10 km/h | 极限超马人物（24 小时跑 260 km+） |
| `GEO-002` 汽车均速 | 120 km/h | 高速长途（500 km / 4h）；不限速高速的写法 |
| `BIO-005` 骨折恢复 | 6 周 | 肋骨/手指类轻骨折在第 4–5 周活动（"临床愈合"≠"能活动"） |
| `PHY-009` 高温 | 55 ℃ 且 `overridable: false` | 架空世界 / 改造人（只会按 major 报，不降档） |
| `TIM-006` 时刻算术 | 容差 1.5h，≥3h 才算 major | 「上午九点出门、工作十二小时、晚上七点回家」若"十二小时"是约数 |
| `PHY-004` 憋气 | 8 分钟 | 受训自由潜水员（要求交代训练经历） |
| `GEO-006` 沙漠+暴雨 | 仅 minor | 沙漠山洪真实存在 |
| `LANG-005` 已逝人物被当在世 | 死亡词 + 亲属称谓 + 同性别代词 | **本库最可能误报的一条**：「母亲去世了，她还坐在门口择菜」里的"她"可能指女儿（已降为 minor 并提示"若指别人请写明主语"） |
| `SOC-006` 购买力 | ≥10000 元的日常小额消费 | 旧币制 / 战时经济 / 恶性通胀背景 |
| `SOC-013` 收入支出 | 同场景、相差 ≥100 倍且 ≥10 万元 | 多人物故事里把 A 的收入与 B 的支出配对 |
| `NUM-007` 时长与「第二天」 | 整段 `parseDuration` 求和 | 同段出现无关时长时会算大 |
| `NUM-001` 人数 | 「一家/兄弟」视为稳定事实 | 跨年添丁若只写弱交代 |
| `NUM-004` 唯一物件 | 名词表 + 排除词 | 「唯一的钥匙」实际指门钥匙与车钥匙 |
| `NUM-008` 能力矛盾 | 同代词 + 12 字施事窗口 | 多人物同用「他」时可能串人 |
| `ANA-006` 日行里程 | 含夸张/比喻排除词 | 直述式「日行千里」（只给 minor） |
| `ANA-002` 容弹量 | `overridable: false` | 这是规则作者唯一的自主判断：已指名现实器物的参数属"数量算术"，架空设定不改变它 |

### 刻意漏报（为压误报而放弃的召回）

1. **多数规则只在单个 segment（句）内取证**——跨句矛盾不报。**这是最大的召回限制，也是误报率低的主因。**
2. 「第二天/翌日」与超长时长不判（起点时刻未知，算不出来）。
3. 序数日期（「第三天」）、年份（「1998年」）、「二米八」这类中文省略写法一律跳过。
4. `GEO-004` 只认坐标表内的 57 座城市，且取前两座配对；多段行程可能漏报。
5. 触发词依赖字面（如 `GEO-003` 必须有「时速/每小时/速度」）。
6. 器物年表只收有共识的年份，朝代以"王朝结束年"为上限 → **晚清器物大量漏报**（宁漏勿误）。
7. `SOC-007` 只在段内出现明确非授权主体时才判 → "他（其实是刑警）调取了档案"漏报。

## 四、维护检查清单

改完任何东西，按顺序跑：

```bash
node --test test/*.test.mjs      # 461 个单元测试
node scripts/sw.mjs selfcheck    # 端到端 76 项断言
node scripts/sw.mjs rules        # 规则库结构自检（id 重复、缺 why/fix、永不产出的规则）
node examples/run-demo.mjs       # 两个示例跑通
```

### 改动时特别注意

- **改 `parseNumber` / `parseDuration` 要格外小心**：它们被 physics / biology / geography / timeline
  四个模块间接依赖。历史上有 5 个静默误判出自这里。改完**必须重跑全部规则测试**。
- **新增规则模块**：在 `lib/commonsense/rules/index.mjs` 的 `REGISTRY` 里注册，
  并在 `PREFIX` 表里加 id 前缀，否则 `sw rules` 会报前缀不符。
- **新增规则**：必须有 `why` 与 `fix`（报告里要给作者看依据），声明 `overridable`
  （决定架空标尺下是否降档），且**至少一个"应命中"+ 一个"不应命中"测试**。
- **不要改回"等子进程退出再判 PDF 成功"**：Chrome 153 写完 PDF 后进程会挂住不退出，
  `lib/export/pdf.mjs` 靠轮询产物（非空 + 大小稳定 + `%PDF-` 头 + `%%EOF` 尾）判定，然后杀进程组。
- **`lib/**` 里不许出现 IO**：读写一律在 `scripts/_io.mjs`。`lib` 是纯函数，这保证了可测试性。
